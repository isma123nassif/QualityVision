### Focus areas: checked and found sound
- **Native memory / pool:** `PinnedMat` frees the pin on ctor failure and disposes the header before unpinning. `MatFrameConverter` returns the rented buffer on every failure path, including the reallocation guard (`:66`). `Frame.Dispose` is idempotent via `Interlocked.Exchange`. Both channels dispose dropped items (`Program.cs:44`, `PhoneFrameSource.cs:46`). `TryWrite`-failed paths dispose (`CameraService.cs:54-57`, `PhoneFrameSource.cs:95-99`). `DetectionService` disposes before the throttle delay. `OpenCvFrameSource` hands `capture`/`raw` to a continuation if a native `Read` is still in flight on cancellation (`:187-200`), which is correct. There is no `await` between `yield return` and `TryWrite`, so ownership cannot be lost on cancellation.
- **Thread-safety:** `CameraStatus` (single `Lock`, consistent snapshot plus freshness check), `FrameBroadcaster` (TCS swapped under lock, `RunContinuationsAsynchronously`, completed outside the lock, published arrays never mutated) and `PhoneFrameSource` (multi-writer channel, `Interlocked` for sequence and timestamp) are all correct. Slow `/stream` clients only skip frames and never block `Publish`. Kestrel's `MinResponseDataRate` drops stalled clients.
- **Reconnect/backoff:** resets on the first frame, doubles to a 10 s cap, catch filter lets shutdown OCE through, source always disposed in `finally`, `Task.Delay` uses `TimeProvider`. The only gap is the open/read timeout (#2).
- **Kestrel:** `Kestrel:Endpoints:Http` 5080 in `appsettings.json`. HTTPS 5443 in a git-ignored `appsettings.Local.json` (`.gitignore:494`) with cert paths outside the repo. Env vars and args are re-added after it, so they still win. No `UseHttpsRedirection`/HSTS. `UseExceptionHandler` in Production. Problem responses keep the status-code re-execute from replacing API errors.
- **Conventions:** CPM respected (no `Version=`). Core has zero packages and no `Microsoft.Extensions.*`. `TimeProvider` used everywhere (no `DateTime.Now`). Structured log templates. `IOptionsMonitor` only in adapters. No `MarkupString`. `.Result`/`.Wait()`/`async void` absent. `Home.razor` uses `PeriodicTimer(…, TimeProvider)` + `InvokeAsync(StateHasChanged)` and cancels on dispose.

Positives:
- Ownership transfer is explicit and commented at every hand-off, and the in-flight-native-read disposal (`OpenCvFrameSource.cs:187-200`) is a subtle case handled correctly.
- The frame endpoint does content-type, magic-byte, streaming size cap and decode-failure checks with German problem details, and never waits for inference.
- `FrameBroadcaster` encodes each frame once for N clients and isolates slow clients cleanly; it is easy to explain in the interview.

Verdict: **APPROVE**: no BLOCKER, and the gates are reported green.
